# FateArk掉线检测 0.0.1
> 定时探测机器人是否还连得上服务器，连续失败后关闭 MCSM 面板。

## 功能
- 每 8 秒向服务器发送一次 `testfor @a`（等待响应，超时 10 秒），用来判断机器人是否还有效。
- 正常响应会把失败计数清零。
- 连续 3 次超时或异常判定为掉线，控制台打印 `FateArk掉线，正在关闭MCSM`。
- 判定掉线后调用 `stop_mcsm()`：Windows 执行 `taskkill /f /im node.exe`，其它系统执行 `pkill -f mcsmanager`，随后 `os._exit(0)` 直接结束进程。
- 检测在插件激活后由单个后台线程运行，不需要玩家或管理员参与。
- 本目录为第三方插件的本地修改版：原作者 `渊思`。

## 前置插件
| 插件 ID | 最低版本 | 用途 |
|---|---|---|
| 无 | - | 不依赖其它插件 |

## 安装
1. 将 `FateArk掉线检测/` 复制到实例的 `插件文件/ToolDelta类式插件/`；
2. 启动实例，或在 ToolDelta 控制台执行 `reload`；
3. 也可以把本仓库添加为自定义插件市场源后直接安装。

## 配置
无配置文件。超时时间（10 秒）、检测间隔（8 秒）、失败阈值（3 次）都写在代码里，不能通过配置调整。

## 指令
本插件无手动指令。控制台会输出以下运行日志：

| 日志关键字 | 含义 |
|---|---|
| `MC响应超时 (n/3)` | 本次 `testfor @a` 超时，累计第 n 次 |
| `检测异常 (n/3): ...` | 本次发送命令抛出其它异常，累计第 n 次 |
| `FateArk掉线，正在关闭MCSM` | 连续失败达到 3 次，开始关闭面板 |
| `MCSM已停止` | `stop_mcsm()` 执行完毕，进程即将退出 |
| `MCSM关闭失败:...` | 关闭命令抛异常，进程仍会以退出码 1 结束 |

## 依赖与兼容
- ToolDelta 1.3.7 类式插件，按 FateArk 启动框架 + MCSM 面板场景编写；
- 仅使用标准库（`time`、`os`、`sys`），无第三方库；
- 只用 `game_ctrl.sendwscmd("testfor @a", waitForResp=True, timeout=10)` 判断连通性，不修改游戏数据；
- 关闭面板是硬编码的：Windows 会结束机器上**所有** `node.exe` 进程，Linux 按 `mcsmanager` 关键字杀进程；与其它 Node 服务同机部署时不要使用；
- 判定掉线后 `os._exit(0)` 直接退出，来不及保存或卸载其它插件，适合「机器人掉线就跟着停面板」的场景；
- 本插件不注册 API（`plugin_entry` 未传 API 名），其它插件无法通过 `GetPluginAPI` 调用；
- 元数据不一致：`datas.json` 的 `version` 是 `0.0.1`、`author` 是 `渊思`，类内 `version` 是 `(1, 0, 0)`、`author` 是 `神秘人`，加载日志会显示 `FateArk掉线检测@1.0.0`。
