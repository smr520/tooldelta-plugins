# 白名单&管理员检测云链联动版 1.1.3
> 按 XUID 校验白名单，并让服务器 OP 与管理员名单保持一致

原作者 猫七街，本目录为本地修改版（FateArk 无 NeOmega 兼容修复）。

## 功能
- **白名单检测**：白名单开启后，玩家进服时按 XUID 校验；不在 `白名单玩家` 中的玩家会被 `kick`，踢出提示词可配置。
- **管理员检测**：对比服务器实际 OP 与 `管理员列表`：名单外却有 OP 的玩家会被 `/say` 警告、`/deop` 并收到提示；名单内却没有 OP 的玩家会被自动 `/op`。
- **周期复查**：后台线程按 `检查时间（秒）`（默认 60 秒）轮询全部在线玩家，补做白名单与管理员检查，覆盖进服事件遗漏。
- **控制台管理**：控制台 `白名单`、`OP操作` 提供交互菜单（添加 / 移除 / 退出），按玩家名解析 XUID 后写入配置并保存。
- **对外管理 API**：以插件 ID 作为 API 名，暴露 `add_whitelist_player`、`remove_whitelist_player`、`add_admin_player`、`remove_admin_player`、`set_whitelist_enabled`、`set_admin_check_enabled`、`set_check_interval`、`get_runtime_status` 等方法，供其他插件联动。
- **无 NeOmega 兼容**：优先用 NeOmega 获取机器人名称；在 FateArk 等没有 NeOmega API 的框架下自动退回 `frame.game_ctrl.bot_name`，不再在 `on_active` 阶段抛出 `ValueError` 导致全部功能不启动。

## 前置插件
| 插件 ID | 最低版本 | 用途 |
|---|---|---|
| `XUID获取` | 0.0.1 | 控制台按玩家名解析 XUID；代码在 `on_preload` 调用 `GetPluginAPI("XUID获取")`，已在 `datas.json` 的 `pre-plugins` 声明 |

本仓库对应目录：`前置_玩家XUID获取`（0.0.8），通过本仓库的插件市场源安装时会自动带上该前置。

## 安装
1. 将 `白名单&管理员检测云链联动版/` 复制到实例的 `插件文件/ToolDelta类式插件/`；
2. 确保已安装 `前置_玩家XUID获取`（插件市场源安装会自动下载），否则 `on_preload` 获取 `XUID获取` API 会失败；
3. 启动实例，或在 ToolDelta 控制台执行 `reload`；
4. 也可以把本仓库添加为自定义插件市场源后安装。

## 配置
配置文件路径：`插件配置文件/白名单&管理员检测云链联动版.json`（首次加载自动生成）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `检查时间（秒）` | `60.0` | 周期检测轮询间隔（浮点数） |
| `白名单.开启状态` | `false` | 白名单检测总开关 |
| `白名单.踢出提示词` | `请先加入白名单` | 未命中白名单时 `kick` 的原因 |
| `白名单.白名单玩家` | `{"xuid1": "player_name1"}` | XUID → 玩家名映射，控制台/API 维护 |
| `管理员检测.开启状态` | `false` | 管理员检测总开关 |
| `管理员检测.提示词` | `你没有管理员权限` | 非法管理员被 `/tell` 的提示 |
| `管理员检测.管理员列表` | `{"xuid1": "player_name1"}` | 合法管理员 XUID → 玩家名映射 |

配置加载时与默认值递归合并，并用 ToolDelta 的 `cfg.check_auto` 校验；校验失败会打印错误并回退默认值，同时写回配置文件。

## 指令
| 位置 | 指令 / 触发词 | 权限 | 说明 |
|---|---|---|---|
| 控制台 | `白名单` | 无 | 交互菜单：`1` 添加白名单、`2` 移除白名单、`q` 退出 |
| 控制台 | `OP操作` | 无 | 交互菜单：`1` 添加管理员、`2` 移除管理员、`q` 退出 |
| 玩家进服 | 自动触发 | - | 按开关执行白名单踢出与管理员状态校正 |
| 后台周期 | 自动触发 | - | 每 `检查时间（秒）` 复查全部在线玩家 |

本插件没有聊天栏或群聊指令。

## 依赖与兼容
- ToolDelta 1.3.7 类式插件（FateArk / MCSM 面板）。
- 依赖 `XUID获取` 前置（已在 `datas.json` 的 `pre-plugins` 声明）。
- 无第三方 pip 库依赖；仅使用 Python 标准库与 ToolDelta 自带模块。
- 代码使用 `tooldelta.internal.launch_cli.FrameNeOmgAccessPoint` 判断启动框架并取 `launcher.omega`，属于 ToolDelta 内部接口，升级 ToolDelta 后需复核兼容性。
- 机器人名称获取失败时为空字符串，此时会跳过“排除机器人自身”的判断。

## 版本记录
- `1.1.3`：修复 FateArk 等没有 NeOmega API 的启动框架下，插件在 `on_active` 直接抛 `ValueError: 此启动框架无法使用 NeOmega API`，导致白名单检测、管理员检测、控制台指令和周期检测全部不启动的问题。

## 说明
- 开启 `白名单.开启状态` 前务必先录入真实 XUID；默认配置里的 `xuid1` / `player_name1` 只是占位符，未替换会让所有未登记玩家被踢出。
- 开启 `管理员检测` 前先录入合法管理员，否则名单外的 OP 会被自动 `/deop`。
- 控制台添加/移除按玩家名解析 XUID（`allow_offline=True`），要求玩家至少登录过一次服务器以留下 XUID 记录。
- 插件名含“云链联动版”，当前代码不直接包含云链/群消息实现，主要通过对外 API 供其他插件联动；机器人自身会被跳过检测。
